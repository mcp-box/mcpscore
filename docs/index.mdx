A missing tool title, a stale protocol version, or an endpoint that accepts
any Origin never crashes your MCP server. Agents pick the wrong tool,
registries rank you lower, and browsers can reach a server they should not.
mcpscore finds those problems in seconds and tells you how to fix each one.
It needs no API key and no sign-up.

This page audits a server on a URL. For a server you run locally over stdio,
start with [Audit a local server](/local-servers).

## Quick start

Run mcpscore against DeepWiki's public MCP server. The `uvx` command needs
[uv](https://docs.astral.sh/uv/getting-started/installation/). The `npx`
command needs Node.js and also uv or pipx on `PATH`, because it launches the
Python engine in an isolated environment
([npm setup](https://github.com/mcp-box/mcpscore/tree/main/npm#requirements)).

<CodeGroup>

```bash uvx
uvx mcpscore https://mcp.deepwiki.com/mcp
```

```bash npx (requires uv or pipx)
npx @mcp-box/mcpscore https://mcp.deepwiki.com/mcp
```

```bash pip
pip install mcpscore
mcpscore https://mcp.deepwiki.com/mcp
```

</CodeGroup>

The first run takes a few seconds longer while the runner downloads the
engine. Then you see the audit:

```text
Welcome to mcpscore!
Attempting Streamable HTTP connection...
Successfully connected to MCP server via Streamable HTTP: https://mcp.deepwiki.com/mcp
Transport: streamable-http
Starting the audit...
✅ Protocol version "2025-11-25" is one of the allowed versions.
✅ Server name is present: "DeepWiki".
❌ Server title is not present in server info. This is an optional quality recommendation. First affected field: server "/serverInfo/title".
  Fix: Add a human-readable serverInfo.title so clients can display a recognizable server name.
  Server · /serverInfo/title · expected a display title
✅ Server uses HTTPS with valid TLS (TLSv1.3).
❌ Streamable HTTP does not reject an invalid foreign Origin with HTTP 403, risking DNS rebinding. Observed HTTP status: 200.
  Fix: Validate supplied Origin headers against the origins allowed for this endpoint. Return HTTP 403 for invalid origins; do not allow every origin to satisfy browser requests.
...
Audit finished. Final score: 78/94
Spec: 2025-11-25 negotiated (latest: 2026-07-28) · era: legacy
Readiness for MCP 2026-07-28: 3/13 (informative — not part of the main score; 4 of 20 checks assessed)
```

That's it. Swap in your own server's URL and you have its score.

Each ❌ is one finding, and the `Fix:` line under it says what to change.
When a finding is about one field, the next line names it. Run the same
command again after a fix and the score moves.

## Reading the result

- **`78/94`** is points earned over points available. A rule is one check,
  like "server title is present". Each rule has a severity, and a failed rule
  costs its weight: CRITICAL 5, HIGH 3, MEDIUM 2, LOW 1. A rule that cannot
  apply to your server is skipped and removed from the maximum, so it never
  counts against you.
- **`era: legacy`** names the MCP lifecycle the server speaks. mcpscore
  scores a server against the spec revision it negotiated, never one it
  does not speak yet.
- **Readiness** is a second score: how ready the server is for the
  2026-07-28 revision. For a legacy server like DeepWiki it is guidance and
  stays out of the main score. For a server already on the stateless
  lifecycle, those points count in the main score.
- The same server gets the same score on the same mcpscore version. The
  [stability contract](/stability) says what may change between versions.

The [methodology](/methodology) covers the four categories (Protocol ·
Primitives · Security & Auth · Readiness) and how each rule is weighted.
