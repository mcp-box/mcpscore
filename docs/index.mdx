MCP servers that break the spec fail in the worst place: silently, inside
someone else's agent. A missing tool description, a stale protocol version, or
an unencrypted endpoint never crashes your server. It makes agents pick the
wrong tool, drop you from their registry, or leak traffic. mcpscore finds that
in seconds, with no API key and no sign-up.

## Quick start

<CodeGroup>

```bash uvx (no install)
uvx mcpscore https://mcp.deepwiki.com/mcp
```

```bash npx (no install)
npx @mcp-box/mcpscore https://mcp.deepwiki.com/mcp
```

```bash uv
uv tool install mcpscore
mcpscore https://mcp.deepwiki.com/mcp
```

```bash pip
pip install mcpscore
mcpscore https://mcp.deepwiki.com/mcp
```

</CodeGroup>

Every ❌ is one thing to fix. Every result cites the spec section or best
practice it enforces, and the same server gets the same score on the same
mcpscore version.

## Reading the result

- **`78/91`** is points earned over points available. Each rule has a weight
  by severity (CRITICAL 5, HIGH 3, MEDIUM 2, LOW 1). Rules that cannot apply to
  your server are skipped and leave the maximum, never failed.
- **`era: legacy`** says which MCP lifecycle the server speaks. Servers are
  scored against the spec revision they negotiated, never against one they
  don't speak yet.
- **Readiness** is a second axis: how ready the server is for the 2026-07-28
  revision. For a legacy server it is guidance. For a server already on the
  new stateless lifecycle those points count in the main score.

The [methodology](/methodology) explains each of these in full.

## Your own server

<CodeGroup>

```bash Python or Node
mcpscore path/to/server.py
mcpscore path/to/server.js
```

```bash Any language
# --stdio runs a command and consumes the rest of the line,
# so put every mcpscore option before it
mcpscore --stdio ./my-go-server
mcpscore --stdio java -jar server.jar
```

```bash Behind auth
mcpscore https://your-server.example/mcp --token "$TOKEN"
mcpscore https://your-server.example/mcp --oauth
```

</CodeGroup>

Local servers need their own runtime on `PATH`. Secrets go in with
`--env NAME` (copied from your environment, never written to the report), not
on the command line. Every flag is in the [CLI reference](/cli).

## Put it in CI

```bash
# Fail the build below 80%, and write the report for later steps
mcpscore https://your-server.example/mcp --fail-under 80 --json > report.json
```

Exit code `3` means the gate failed. `1` means the audit never ran, `2` means
it could not connect, `0` means it passed. The
[GitHub Action](/github-action) turns this into one step with a PR comment.
